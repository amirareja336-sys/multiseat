  ### 1. Why a "VGA" User Was Created with an Unknown Password                                                                                             
                                                                                                                                                           
  In multiseat-mint.sh (lines 107–129), whenever a seat does not have an explicit username specified in the config, it runs fallback guest provisioning:   
                                                                                                                                                           
    user=${1/card/u}      # Replaces 'card' with 'u' (e.g. card0-VGA-1 -> u0-vga-1)                                                                        
    user=${user,,}                                                                                                                                         
    ...                                                                                                                                                    
    if [ ! -d $user_home/Desktop ]                                                                                                                         
    then                                                                                                                                                   
        useradd $user > /dev/null 2>&1                                                                                                                     
                                                                                                                                                           
  • Where the name came from: The script detected your connected VGA monitor output (such as card0-VGA-1) and generated a username like u0-vga-1.          
  • Why the password was unknown: It invoked useradd without setting a password or using -p. On Ubuntu/Mint, this creates an account with its password     
  locked (! in /etc/shadow).                                                                                                                               
  • Why it appeared on your login screen: LightDM (Linux Mint's Slick Greeter) automatically displays any account in /etc/passwd with a UID ≥ 1000. Since  
  useradd assigned a standard human UID, LightDM displayed the new VGA user on the login screen, but because the account had no password configured, you   
  were locked out.

  ### 2. Why the Boot Indicator Slowed Down and Froze on the Mint Boot Screen                                                                              
                                                                                                                                                           
  The freeze on the Plymouth boot splash screen was caused by a combination of DRM master contention, boot dependency deadlock, and an infinite restart    
  loop:                                                                                                                                                    
                                                                                                                                                           
  │ Diagram exceeds terminal width (186 > 157 cols)                                                                                                        
  │ Displayed as code block. Widen terminal to view inline.                                                                                                
                                                                                                                                                           
    flowchart TD                                                                                                                                           
        A["Boot: Plymouth holds /dev/dri/card0 (DRM Master)"] --> B["multiseat.service starts (Before=display-manager.service)"]                           
        B --> C["multiseat-mint.sh -S runs drm-lease-manager"]                                                                                             
        C --> D["drmSetMaster() fails (device busy with Plymouth)"]                                                                                        
        D --> E["drm-lease sockets never appear; wait_files hangs"]                                                                                        
        B -.->|Blocks| F["LightDM cannot start"]                                                                                                           
        F -.->|Cannot run| G["plymouth --quit never called"]                                                                                               
        H["labwc respawns every 1s (Restart=always)"] --> I["Heavy KMS/DRM & VT thrashing"]                                                                
        I --> J["Plymouth frame loop starves & freezes"]                                                                                                   
                                                                                                                                                           
  1. DRM Master Conflict with Plymouth:                                                                                                                    
  During boot, Plymouth displays the Linux Mint logo and blinking cursor by holding the GPU (/dev/dri/card0) as the Linux DRM Master. When                 
  multiseat-mint.sh (lines 567–582) launched drm-lease-manager, it attempted to take DRM Master status. Because only one process can be DRM Master at a    
  time, drm-lease-manager failed to initialize.                                                                                                            
  2. Deadlock with LightDM:                                                                                                                                
  multiseat-mint.sh (line 259) defined the systemd unit with:                                                                                              
    Before=display-manager.service                                                                                                                         
  LightDM is the service that normally tells Plymouth to release the screen (plymouth --quit). Because multiseat.service blocked display-manager.service   
  while itself hung waiting for DRM leases (wait_files), LightDM could never start, and Plymouth was never told to quit.                                   
  3. Infinite Crash-Restart Loop & VT Thrashing:                                                                                                           
  In multiseat-mint.sh (lines 131, 152), the seat compositor (labwc) was launched with:                                                                    
    resta="--property=RestartSec=1s --property=Restart=always "                                                                                            
  Because the DRM lease was missing and the new user had no active PAM runtime directory (/run/user/$user_id), labwc crashed immediately and systemd       
  respawned it every single second.                                                                                                                        
  4. Concurrently, line 614 executed deallocvt and stopped getty*. This flood of crashing compositors, VT disruptions, and repeated DRM acquire attempts   
  starved Plymouth's render thread, causing the cursor to blink slower and slower until the graphics driver completely locked up.

  ### 3. How to Fix This                                                                                                                                   
                                                                                                                                                           
  #### Step A — Enable the Boot Failsafe                                                                                                                   
                                                                                                                                                           
  While debugging multiseat, prevent automatic boot freezes by uncommenting the safety disable check at line 13 of multiseat-mint.sh:
  
    [[ "-S" == "$1" ]] && systemctl disable multiseat
  
  (If the service fails or is tested, it will automatically disable itself so the next reboot boots normally into LightDM without needing recovery mode.)  
  
  #### Step B — Fix the Boot Ordering in multiseat.service
  
  The service must not block display-manager.service, and must wait until Plymouth has completely released the display. In
  multiseat-mint.sh (lines 254–269), update the unit definition:
  
    [Unit]
    Description=MultiSeat Launcher
    After=multi-user.target plymouth-quit-wait.service
    Wants=plymouth-quit-wait.service
  
    [Service]
    ExecStart=/path/to/multiseat-mint.sh -S
    ExecStopPost=/path/to/multiseat-mint.sh -q
    RemainAfterExit=yes
    Restart=no
    Type=simple
  
  #### Step C — Fix the User Creation & LightDM Leak
  
  To prevent phantom users from showing up on your LightDM login screen:
  
  1. Assign your actual user or configure a known password: In your /etc/multiseat/*.conf file, explicitly specify which user logs into each seat rather   
  than letting the script auto-generate u0-...:
    card0-HDMI-A-1
        user senay
  
  2. If guest accounts are created: Either set a passwordless login (passwd -d $user and add to group nopasswdlogin), or hide the user from LightDM by     
  telling AccountsService it is a system user:
    sudo mkdir -p /var/lib/AccountsService/users
    echo -e "[User]\nSystemAccount=true" | sudo tee /var/lib/AccountsService/users/$user
  

  #### Step D — Remove deallocvt from -S
  
  In multiseat-mint.sh (lines 611–614), ensure deallocvt and killing root sessions only happen during interactive testing (-s), never in daemon background 
  mode (-S):
  
    if [[ "$1" == "-s" ]]; then
        read -p " waiting to stop root session ..."
        O=$(loginctl | grep root) && loginctl kill-session ${O:0:7}
        systemctl stop getty*
        deallocvt
    fi
